## 从一个熟悉的动作开始

打开浏览器，输入一个网址，然后按下回车。这件每天都会发生的小事，背后是一整套精密协作的系统。

学习计算机网络时，可以先建立一张地图：**每一层解决什么问题，它向上一层提供什么能力？** 有了这张地图，再去理解具体协议会轻松很多。

> 把网络想象成一场接力。每一层处理自己的问题，通过清晰的接口连接成完整的过程。

## 为什么需要分层

如果把寻址、可靠传输、数据编码和网页语义都写进一个协议，每次修改都可能牵动整个系统。分层让复杂度有了边界。

以常见的五层教学模型为例：

| 层次 | 主要职责 | 常见例子 |
| --- | --- | --- |
| 应用层 | 定义应用交换信息的规则 | HTTP、DNS |
| 传输层 | 进程之间的数据传输 | TCP、UDP |
| 网络层 | 跨网络寻址与转发 | IP |
| 数据链路层 | 相邻节点之间传输帧 | Ethernet |
| 物理层 | 在介质上传送比特 | 电信号、光信号 |

不同教材对层次的划分可能不同，理解职责比记住层数更重要。

### 封装与解封装

应用层产生的数据会逐层添加控制信息。例如 TCP 报文段被放进 IP 数据报，IP 数据报又被装入链路层帧。接收端反向处理这些信息，把数据交给目标进程。

## 一次请求的路径

以下是一个简化过程，真实情况还会受到缓存、代理和协议版本影响。

1. 浏览器解析 URL，确定目标主机和资源。
2. 通过 DNS 或本地缓存获得目标地址。
3. 建立适当的传输连接；HTTPS 还需要安全协商。
4. 发送请求，服务器生成响应。
5. 浏览器解析响应并展示页面。

### 用命令观察响应

可以从响应头观察服务器返回的信息：

```bash
curl -I https://example.com
```

这里的 `-I` 会请求响应头。状态码、缓存字段和内容类型，都是理解一次请求的入口。

## 延迟来自哪里

一个数据包的总时延通常可以拆成处理、排队、发送和传播四部分。

- **处理时延**：检查头部、判断转发位置所需时间。
- **排队时延**：等待链路空闲所需时间。
- **发送时延**：把所有比特送到链路上的时间。
- **传播时延**：信号在物理介质中行进的时间。

链路带宽增加，可以减少发送时延，但不意味着传播距离变短。把两者区分开，是分析网络性能的基础。
